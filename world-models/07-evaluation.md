# 07 · 怎样让别人相信，而不是只让自己兴奋

[目录](README.md) · 上一章：[因果](06-causality.md) · 下一章：[论文工作流](08-paper-workflow.md)

## 先写主张，再选指标

“更强”不是一个可测试的完整句子。“在相同交互预算下，对未见目标位置的控制成功率更高”才接近可测主张。

| 主张 | 更匹配的证据 | 不能偷换成 |
| --- | --- | --- |
| 视觉更好 | 固定输入的盲评、渲染指标、失败率 | 物理更正确 |
| 几何更好 | 未见视角、深度/表面误差、尺度说明 | 控制更可靠 |
| 预测更好 | 多跨度误差、事件预测、校准 | 所有任务更强 |
| 控制更好 | 闭环成功率、代价、交互与规划预算 | 通用智能 |
| 产品可交付 | 真实用户输入、延迟、导出、成本、故障恢复 | 自研基础模型领先 |

PSNR测像素差异的一种形式，不单独衡量物理理解。特征距离也不必然反映用户关心的错误。学习指标与产品指标应一起报告，不能只挑好看的那个。

## 三类划分一定要分清

- 同分布测试：新的独立样本，但条件类似训练。
- 组合泛化：已见因素出现新的组合。
- 分布外测试：新对象、新动作范围、新材质、不同物理参数或传感器条件。

按源视频和场景划分；去重；记录预训练数据可能重叠的未知风险。“我没有主动拿测试集训练”不等于能排除大规模预训练污染。

## 第三方榜单有什么用？

榜单能在特定协议下提供外部可比性，不能免除方法审核。自己在本地跑了官方代码，应称“按该协议进行的本地评测”；只有维护方接受并发布的条目，才能称“官方榜单记录”。独立复现比你重复跑自己代码增加了另一层证据。

核对任务、版本、赛道、输入条件、是否允许额外数据、提交次数、是否可挑样本和是否披露最佳采样。不要用某一子项的最好值声称总榜第一。

入门例子：[Physion](https://physion-benchmark.github.io/)讨论视觉物理预测；[Physion++](https://dingmyu.github.io/physion_v2/)关注需要推断隐藏物理属性的预测；[Physics-IQ](https://github.com/google-deepmind/physics-iq-benchmark)是生成视频物理理解评测入口。名字相近不代表数据、指标或任务相同。固定版本后阅读其README及原论文，不能互换分数。

## 一个可执行的最小协议

1. 在实验前写下主指标、数据划分和比较对象。
2. 冻结测试集；开发只看训练与验证。
3. 固定两组的输入、预处理、预算及停止规则。
4. 用多个独立随机种子；报告每次值、均值、离散程度与样本数。
5. 保存所有失败、超时和无效输出；不悄悄删除。
6. 对改动做消融，至少能区分数据、容量、计算量和核心设计。
7. 导出复现命令、版本、结果文件及可公开的样例。

同一视频的100帧不是100个独立世界。做统计区间时，应按独立场景/轨迹单位考虑相关性；样本少时直说不确定，别把小数位数当作可信度。

## 结果表的最低字段

`任务｜数据版本｜独立样本数｜种子｜基线｜方法｜主指标｜失败数｜训练/推理预算｜额外数据｜代码提交｜局限`

每一个数字应该能回到原始文件。截图、点赞数、新闻报道、调用别人API得到的效果，都不能冒充自研世界模型能力的评测证据。
