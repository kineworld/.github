# 08 · 从“看过论文”到“能复现和质疑”

[目录](README.md) · 上一章：[评测](07-evaluation.md) · 下一章：[资料地图](09-resources.md)

读论文不是逐字翻译比赛。先判断问题是否与你有关，再弄清方法，最后检查证据是否支持主张。

## 第一遍：建立地图，不急着理解全部公式

写下五句话：作者解决什么任务、以前为什么做不好、改变了什么、用什么证明有效、哪些地方没有证明。摘要用于了解作者想表达什么，实验和局限用于判断实际证明了什么。

对世界模型论文，第一眼就找输入和输出：观察是图像还是状态？动作是真实控制量还是潜在动作？预测是像素、特征、奖励还是几何？测试是离线视频还是闭环交互？如果这些没搞清楚，先不要比较分数。

## 第二遍：沿一次数据流追代码

从数据加载器找出一个batch，把每个张量的形状、单位和来源记下来。继续追编码器、预测器、目标分支、损失和优化器。然后单独追推理/规划入口。

重点找这些错位：

- 训练可用的未来信息，是否误进入测试输入？
- 目标特征来自哪一个编码器？权重是否更新？
- 动作是否归一化？是在当前帧前还是后执行？
- 随机裁剪是否破坏动作与图像的空间关系？
- 训练时输入真实状态，测试时是不是输入自己的预测？
- 推理样例是否只是特征提取，而不是完整规划？

不认识的数学符号只追到当前需要的深度。例如先弄懂KL散度在代码里约束哪两个分布，再研究全部理论；不要一边不懂数据流，一边改十个损失系数。

## 第三遍：把复现拆成四道门

1. **环境门**：固定提交、依赖、权重来源与哈希；运行作者最小示例。
2. **数值门**：输出形状正确、无NaN、保存加载一致，检查预处理和单位。
3. **行为门**：输入变化是否产生预期变化？打乱时间和动作会怎样？
4. **指标门**：按原协议测量，核对数据、预算、种子和失败处理。

“程序能运行”只过了第一部分；“生成了一个视频”也不是完成论文复现。差距大时，先排查数据和评测口径，不急着宣布原论文不可复现。

## 一页论文卡：复制后填写

```text
标题 / 作者 / 原始链接：
论文版本与代码提交：
研究问题（不用宣传形容词）：
输入 → 内部状态 → 输出：
训练数据 / 动作来源 / 可观测假设：
核心改动（最多三点）：
损失与推理过程：
主要证据 / 对照 / 计算预算：
最值得怀疑的替代解释：
无法从本文确认的事项：
我能在现有硬件验证的最小问题：
复现命令 / 实际结果文件：
下一步：采用 / 暂缓 / 不适合，理由：
```

## 用AI加速，但不要把判断外包

可让AI解释公式、追踪函数、生成单元测试、检查张量形状和整理失败日志。要求它指出依据的位置；让它区分“论文写了”“代码显示”“我推测”。

可复制的学习提示词：

> 我正在学习这篇论文及指定版本代码。先问我三个基础问题判断起点，再用杯子或小车举例解释。沿一个样本追踪输入、状态、预测、目标和损失。每项关键事实给出原文段落或文件位置；找不到就说不知道。不要替我伪造实验，不替我下载大文件或调用付费服务。讲完后给我一道反例题，让我先回答，再纠错。最后指出一个在CPU或小显存设备上可验证的命题，以及它不能证明什么。

不要把未授权论文全文、私有数据或密钥提交给第三方工具。运行AI生成的命令前检查文件操作、联网、下载量、服务费用和许可证。测试代码也需要审查：一个只验证自己预设结论的测试，不能替代独立证据。

## 学得快的实际方法

每次结束写三句话：今天理解了什么；哪个结果推翻了直觉；下一次只改变哪个变量。隔一段时间合上资料，用自己的话重新讲一遍。讲不清的地方就是下一轮学习重点。
