# Support

## Before you ask

This organization is **research-stage** and has **one part-time maintainer**. Read this page
first — it will save you a round trip.

## What we can help with

| Topic | Channel | What to include |
| --- | --- | --- |
| Broken documentation, dead link, typo | Issue, or a pull request | The file and the line |
| A lab or guide script that does not run | Issue (*Bug report*) | Command, Python version, full traceback |
| Clarifying a claim made in a repository | Issue (*Evidence challenge*) | The claim and the artifact it points at |
| Reporting a reproduction attempt | Issue (*Reproduction report*) | Commit SHA, hardware, raw numbers |
| Security problem | See [`SECURITY.md`](SECURITY.md) | — |
| Learning-guide content questions | Issue in [`.github`](https://github.com/kineworld/.github/issues) | Which chapter, which paragraph |
| Licensing or reuse questions | Issue in [`.github`](https://github.com/kineworld/.github/issues) | Repository and intended use |

## What we cannot help with

Being explicit about this is part of the project's honesty.

- **No support SLA.** There is no guaranteed response time. Replies may take days, and some
  questions will not get one.
- **No debugging of your environment.** We can confirm whether an issue is reproducible from a
  clean clone; we cannot administer your machine, driver stack, or cluster.
- **No upstream projects.** 14 repositories here are forks. For anything in
  [`ATTRIBUTION.md`](ATTRIBUTION.md), ask the upstream project — we do not maintain that code.
- **No private model or infrastructure access.** We do not hand out weights, datasets, service
  credentials, or compute, and we do not run experiments on request.
- **No business, investment, or career advice.** Not a support topic.
- **No endorsement requests.** We do not provide quotes, badges, partnership statements, or
  "featured by KineWorld" logos.

## Paid support

There is none. This is an unfunded research-stage project. If that changes, this file will say so.

## Reporting a claim you believe is wrong

That is welcome, and it is the most useful thing you can send us. Open an *Evidence challenge*
issue with the specific claim, the artifact that supports it, and what you observed instead.
If we agree, the claim gets corrected in place with a visible note saying it was corrected.
Corrections are not quietly deleted.
